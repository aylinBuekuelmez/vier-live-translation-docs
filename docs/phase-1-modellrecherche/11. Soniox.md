# 11\. Soniox

**Recherche-Stand: 18.10.2026. Relevante Modelle :**

- Realtime STT(Speech to text) + Translation: **stt-rt-v5**
- Realtime TTS(Text to speech): **tts-rt-v2**
- Speech-to-Speech: Kombination dieser beiden APIs

## **Kurzüberblick**

Soniox bietet keine direkte End-to-End-S2ST-Blackbox (S2ST=Speech to Spreech translation), sondern eine **eigene Streaming-Pipeline**: Realtime-STT-API erkennt Sprache + übersetzt sie gleichzeitig als Text → dieser übersetzte Text wird dann an die streamingfähige Soniox-TTS-API weitergegeben (diese Kombination = **Real-time speech-to-speech translation)**. 

Pipeline = mehrere Verarbeitungsschritte werden hintereinander geschaltet                                     Blackbox = internen Zwischenschritte sind für uns nicht sichtbar

Beide Stufen können bereits arbeiten, bevor ein kompletter Satz beendet wurde.[ ](https://soniox.com/docs/translation/get-started?utm_source=chatgpt.com)

Telefon-Audio → Soniox stt-rt-v5 → Transkription + Realtime-Übersetzung →  Soniox tts-rt-v2 → übersetztes Audio

### **1. Realtime und Streaming**

Die STT/Translation-API läuft über einen persistenten **WebSocket(**hält dauerhafte Verb. offen  → dadurch kann man ständig kleine Audio senden und ständig Erg. zurückbekommen). Soniox kann translation mitten im Satz ausgeben → wahrgenommene Latenz kann sinken.[ ](https://soniox.com/docs/translation/stt-translation/rt-translation?utm_source=chatgpt.com)

### **2. Sprachen**

offizielle Liste enthält ausdrücklich für STT, Tranlation, TTS/S2S (one-way sowie two-way): Deutsch, Englisch, Polnisch, Bulgarisch, Französisch, Italienisch, Spanisch  

### **3. Telefonie**

STT akzeptiert unter anderem: μ-law, A-law, PCM, AMR, OGG, WAV etc.

Realtime-API kann Raw-Audio mit konfigurierbarer Einheit für Audiosignal z.b. Hz verarbeiten.[ ](https://soniox.com/docs/stt/rt/real-time-transcription?utm_source=chatgpt.com)

Auch TTS kann **pcm\_mulaw und pcm\_alaw bei 8.000 Hz** ausgeben( diese Formate sind für klassische Telefonie relevant) 

### **4. Fachbegriffe, Namen, IDs usw.**

context-Obj. = Sammlung von Inf. z.b. diese Begriffe können im Gespräch vorkommen (Firmenname,..)

Soniox bietet ein `context`-Objekt mit: `general, text, terms, translation_terms`

Einen schwierigen Fachbegriff mit einer gewünschten Übersetzung hinterlegen. Soniox nennt hierfür ausdrücklich technische Begriffe und Entity-Namen als Use Cases.[ ](https://soniox.com/docs/stt/concepts/context?utm_source=chatgpt.com)

Zusätzlich nennt Soniox für `stt-rt-v5` Verbesserungen bei strukturierten Angaben wie **Zahlen, Daten, E-Mail-Adressen, Namen, Adressen und Codes**(Achtung: Anbieterangabe, muss noch getestet werden)[ ](https://soniox.com/docs/stt/models?utm_source=chatgpt.com)

### **6. Preise**

Aktuelles offizielles Soniox-Pricing: **Realtime STT **≈ **$0,12 pro Audiostunde **

Wichtig: $0,12/h sind laut Soniox eine ungefähre Äquivalenz aus Token-Nutzung, kein universeller Festpreis pro Stunde.

Technisch wird tokenbasiert abgerechnet:

- Realtime Audio Input: $2,00 / 1 Mio. Tokens
- Realtime Text Output: $4,00 / 1 Mio. Tokens
- Kontext/Input Text: ebenfalls tokenbasiert

**Translation:** laut aktueller Pricing-FAQ im selben Realtime-STT-Aufruf enthalten; kein separater Translation-Service-Aufpreis.

**TTS:** ungefähr **$0,70 pro Stunde generierter Sprache**, ebenfalls tokenbasiert.<https://soniox.com/pricing>

bedeutet später ungefähr: Speech-to-Speech-Kosten = STT + Translation + TTS

Da Translation im STT-Aufruf integriert ist, besteht die Pipeline wirtschaftlich hauptsächlich aus: Realtime STT/Translation +TTS-Ausgabe
